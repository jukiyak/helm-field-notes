trigger 「第二の書き手」は誰か

α 再審トリガーの一文は「seaseed 知識に第二の書き手が必要になる」。組織として自分の権限境界を持つ人。AI エージェントの書き込み頻度とは別物。

トリガー（再審する）
Sea Seed 知識に従業員・共同経営者など、自分の権限境界を持つ人間の書き手が要る / 売却・監査・清算で開示単位が要る / Hydrogie が自前知識 vault を実証 / 2軸スコープが月次で破綻
いま（トリガー未発火）
Grok → Claude → GPT の順で書き込み頻度が高い。オーナー権限下のエージェント。Sea Seed に別アカウント・別リポ境界が必要、という話ではない。

2軸4軸 来歴と tradeoff

2軸は redesign draft 3 の実装寄り統治語彙。4軸は薄い intent（N6 解除後）の所有・時間・今回の契約の語彙。1対1 に潰さない（昨日の裁定）。

2軸 — domain / exposure

domain
誰の世界の情報か
self / family / helm / seaseed / hydrogie …
exposure
どこまで見せてよいか
public / internal / sensitive / private

長所

  • 機械可読・スコープ強制しやすい
  • sparse / export のパス集合に落ちる
  • 実装単位が少ない

短所

  • 管理主体・時点・今回の作業契約を直接表さない
  • ストア所在・ポータビリティとは別レイヤ

4軸 — 管理 / 閲覧 / 作業スコープ / 時点

管理
誰が正しさと出口（export）を引き受けるか
閲覧
誰が・どこで見られるか（UI 面 ≠ 正本）
作業スコープ
今このセッションに渡してよい文脈
時点
いつの世界線か（スナップショット・乗り換え）

長所

  • 所有・権限・「今の作業」を分けられる
  • N6 解除後の「所在は前提でない」と相性がいい

短所

  • frontmatter 2キーのような実装スキーマに未落下
  • domain/exposure と 1:1 対応しない
いまの緊張（REVISIT の意味） 2軸 = 何を注入し、委任し、切り出すか。
4軸 = 誰が責任を持ち、いつの話で、今どこまで触るか。
domain に「管理」を押し込むと export 主体が曖昧になる。作業スコープを exposure だけでやると、同じ sensitive でも「今日のチケット」と「全社検索」が区別できない。
→ β を捨てるのではなく、突き合わせる前に confirmed しない。次は対応表か、従属関係の決定。
